# デモ用チケット一覧

各場面で Jira に登録しておくチケットの文面です。そのまま Jira に貼り付けて使えます。
ID は Jira プロジェクトキーを `RB` にした場合の例です。

---

## 場面1：並行開発（3つの独立したチケットを3つのエージェントに同時に割り当てる）

### RB-1 予約一覧に日付フィルタを追加する
**種類:** タスク
**説明:**
予約一覧画面の上部に日付の入力欄を置き、選んだ日付の予約だけを表示できるようにする。
- 未選択のときは全件表示（現在の動作のまま）
- 「すべて表示」ボタンでフィルタを解除できる
- 対象ファイル: `src/pages/Reservations.jsx`

### RB-2 会議室カードに定員を表示する
**種類:** タスク
**説明:**
会議室画面の各カードに定員（`capacity`）を「定員 12 名」の形式で表示する。
データはすでに `src/data.js` の `rooms` に入っている。
- 対象ファイル: `src/pages/Rooms.jsx`

### RB-3 設定画面にダークモード切り替えを追加する
**種類:** タスク
**説明:**
設定画面に「ダークモード」のトグルを追加し、ON のとき画面全体を暗い配色にする。
- `src/index.css` の CSS 変数を上書きする方式で実装する
- 状態は `App.jsx` で持ち、`<html>` に `data-theme="dark"` を付ける
- 対象ファイル: `src/pages/Settings.jsx`, `src/App.jsx`, `src/index.css`

> 3つとも触るファイルが重ならないので、同時に進めても衝突しない。

## 場面2：比稿（同じチケットを複数のエージェントに投げて結果を比べる）

### RB-4 同じ会議室の時間帯が重なる予約を防ぐ
**種類:** タスク
**説明:**
現在は同じ会議室・同じ日付・重なる時間帯でも予約できてしまう。
新規予約時に重複を検出し、予約できないようにしてほしい。
実装方法は任せる。どこで検出するか、どう利用者に伝えるかも含めて提案すること。

> 「どこで判定するか」「エラー表示をどうするか」「空き時間を提案するか」など解釈の幅があるので、
> エージェントごとに違う答えが返ってきやすい。

## 場面3：diff に直接コメントしてエージェントに直させる

チケットは不要。場面1か場面2の成果物の diff を開き、任意の行にコメントを書いて送り返す。
例:
- 「このエラー文言は他画面と合わせて敬体にして」
- 「この判定は `data.js` 側に関数として切り出して」
- 「変数名を `filtered` ではなく `visibleReservations` に」

## 場面4：チケットからそのまま開発

### RB-5 終了時刻が開始時刻より前でも予約できてしまう
**種類:** バグ
**説明:**
**再現手順**
1. 新規予約画面を開く
2. 開始 14:00、終了 13:00 と入力する
3. 「予約する」を押す

**期待する動作**
「終了時刻は開始時刻より後にしてください。」と表示され、予約は登録されない。

**実際の動作**
そのまま登録され、予約一覧に「14:00–13:00」と表示される。

**補足**
- 対象ファイル: `src/pages/NewReservation.jsx`
- 既存の件名未入力チェックと同じ仕組み（`error` state）で表示する

> 説明が具体的なので、チケットを読ませるだけで完了まで進みやすい。

## 場面5：ブラウザ上で UI 要素を直接指定して変更させる

チケットは任意。Orca の Design Mode で画面上の要素をクリックし、そのままプロンプトに送る。
例:
- ヘッダーのナビゲーションをクリック → 「選択中のタブの下線をもっと太くして、色もアクセント色に」
- 「予約する」ボタンをクリック → 「このボタンを右寄せにして幅いっぱいに」
- 会議室カードをクリック → 「カードにホバー時の影を付けて」

必要なら以下を登録:

### RB-6 ヘッダーの見た目を調整する
**種類:** タスク
**説明:**
ヘッダーのブランド名を少し大きくし、選択中タブの下線を太くする。
